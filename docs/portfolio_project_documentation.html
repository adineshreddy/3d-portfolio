3D Portfolio Project Documentation

Detailed implementation guide for Dinesh Reddy Ande's React, Vite, Three.js, GSAP, and Tailwind CSS portfolio.

Project: three-d-portfolio-2025
Framework: React 19 + Vite
Primary UI: Tailwind CSS 4
3D Stack: Three.js, React Three Fiber, Drei
Animation: GSAP + ScrollTrigger
Profile: Backend, cloud, AI/RAG, and full-stack engineering
Purpose of this document: This guide explains the project from browser entry to final rendered sections. It covers what was implemented, why each file exists, how data flows through the app, and how the portfolio presents Dinesh's resume-based experience, projects, and skills.

1. Executive Summary

This project is a single-page interactive 3D portfolio application. It uses Vite as the development/build tool, React as the UI framework, Tailwind CSS for layout and visual styling, GSAP for entrance and scroll-triggered animations, and React Three Fiber/Drei for 3D rendering. The site is personalized around Dinesh Reddy Ande's profile: software engineering experience at Infosys and OneAdvanced, graduate study at the University of Florida, backend systems, cloud infrastructure, and AI/RAG work.

The application is intentionally component-based. Each major page area is isolated in a section component, while reusable pieces such as the navbar, buttons, glowing cards, counters, and 3D model cards are placed under src/components. Most profile content is centralized in src/constants/index.js, which makes future editing simpler because text, metrics, experience items, tech-stack labels, and links can be updated without rewriting the section components.

Implemented at a glance

  • Browser tab branding with Dinesh's name and a custom DR favicon.
  • Responsive navigation with scroll-aware background behavior.
  • Hero section with animated rotating keywords and a 3D room scene.
  • Resume-based counters for experience, transaction scale, API improvement, and ML precision.
  • Text-first project showcase replacing template screenshots with polished project cards.
  • Animated marquee of technical skills.
  • Feature cards that summarize backend, AI/RAG, and cloud delivery strengths.
  • Professional experience timeline with Infosys and OneAdvanced roles.
  • Interactive 3D tech stack cards using GLB models.
  • Footer social links for GitHub, email, and LinkedIn.

4. Browser Entry and React Bootstrapping

The browser first loads index.html. This file does not contain the full UI. Instead, it defines a root element and points the browser to src/main.jsx. The title and favicon shown in the browser tab are also configured here.

<link rel="icon" type="image/svg+xml" href="/images/fav.svg" />
<title>Dinesh Reddy Ande - Portfolio</title>

<div id="root"></div>
<script type="module" src="/src/main.jsx"></script>

The React application starts in src/main.jsx. It imports the global CSS file, imports the main App component, and renders it inside the root div.

import './index.css'
import App from './App.jsx'

createRoot(document.getElementById('root')).render(
  <StrictMode>
    <App />
  </StrictMode>,
)

This separation is important: index.html is the shell, while React owns the actual interactive interface after mounting.

The high-level page structure is in src/App.jsx. This file works like the master layout for the single-page portfolio. It imports each section and renders them in the order visitors see them.

7. Navigation Bar

The navigation bar is implemented in src/components/NavBar.jsx. It has three responsibilities: display the site owner name, render section links from the constants file, and provide a direct email action.

const [scrolled, setScrolled] = useState(false);

useEffect(() => {
  const handleScroll = () => {
    const isScrolled = window.scrollY > 10;
    setScrolled(isScrolled);
  };

  window.addEventListener("scroll", handleScroll);
  return () => window.removeEventListener("scroll", handleScroll);
}, []);

The scroll listener changes the navbar class between scrolled and not-scrolled. In src/index.css, those classes control whether the navbar background is transparent or black.

<header className={`navbar ${scrolled ? "scrolled" : "not-scrolled"}`}>
  ...
</header>

9. 3D Hero Scene

The 3D hero scene is implemented in src/components/models/hero_models/HeroExperience.jsx. It uses React Three Fiber's Canvas component to create a WebGL scene inside React.

<Canvas camera={{ position: [0, 0, 15], fov: 45 }}>
  <ambientLight intensity={0.2} color="#1a1a40" />
  <OrbitControls
    enablePan={false}
    enableZoom={!isTablet}
    maxDistance={20}
    minDistance={5}
    minPolarAngle={Math.PI / 5}
    maxPolarAngle={Math.PI / 2}
  />

  <Suspense fallback={null}>
    <HeroLights />
    <group scale={isMobile ? 0.7 : 1} position={[0, -3.5, 0]}>
      <Room />
    </group>
  </Suspense>
</Canvas>

The scene adjusts scale based on screen width using react-responsive. On smaller screens, the room is scaled down to avoid cropping. The falling particle layer was removed by deleting the Particles import and the <Particles count={100} /> render call from this file.

10. Animated Counter Metrics

The counters are implemented in src/components/AnimatedCounter.jsx. They display measurable resume highlights and animate when the counter section scrolls into view.

gsap.to(numberElement, {
  innerText: item.value,
  duration: 2.5,
  ease: "power2.out",
  snap: { innerText: 1 },
  scrollTrigger: {
    trigger: "#counter",
    start: "top center",
  },
  onComplete: () => {
    numberElement.textContent = `${item.value}${item.suffix}`;
  },
});

The final suffix is applied after the count animation completes. This allows values such as 1M+, 70%, and 98% to appear cleanly.

15. Glow Card Mechanism

The glow effect is implemented in src/components/GlowCard.jsx. It tracks the mouse position relative to the card, calculates an angle, and writes that angle into a CSS custom property named --start.

const rect = card.getBoundingClientRect();
const mouseX = e.clientX - rect.left - rect.width / 2;
const mouseY = e.clientY - rect.top - rect.height / 2;

let angle = Math.atan2(mouseY, mouseX) * (180 / Math.PI);
angle = (angle + 360) % 360;

card.style.setProperty("--start", angle + 60);

The CSS then uses that variable inside a conic gradient mask to create a directional border glow.

.card::before {
  background: var(--gradient);
  mask: linear-gradient(#0000, #0000),
    conic-gradient(
      from calc((var(--start) - 15) * 1deg),
      #ffffff1f 0deg,
      white,
      #ffffff00 100deg
    );
  opacity: 0;
}

.card:hover::before {
  opacity: 1;
}

19. Responsiveness

The project handles responsiveness through Tailwind breakpoints and React media queries. Tailwind classes such as md:, xl:, and 2xl: change layout, spacing, text size, and card dimensions at different screen widths.

The hero 3D scene also uses runtime media queries:

const isMobile = useMediaQuery({ query: "(max-width: 768px)" });
const isTablet = useMediaQuery({ query: "(max-width: 1024px)" });

These values control 3D room scale and whether zoom is enabled for OrbitControls. This prevents the 3D scene from feeling awkward on tablets and mobile devices.

22. Recommended Future Improvements

  1. Add real project links: Add GitHub/demo links to the project cards once the repositories are public or ready to share.
  2. Code-split 3D sections: The production build warns that the JavaScript chunk is large. Dynamic imports for 3D sections would improve initial load performance.
  3. Replace placeholder social icons: The footer links are correct, but the icon image files are inherited from the template. Replacing them with GitHub/email/LinkedIn-specific SVGs would improve polish.
  4. Add accessibility labels: Some decorative images have empty alt text, which is acceptable, but interactive icons could be made more explicit.
  5. Add a resume download button: A direct PDF resume link could be added to the navbar or hero CTA area.
  6. Optimize 3D assets: GLB models should remain compressed and lightweight to protect page speed.
